状态含义：

- `历史记录`：早期 WebView Cookie 流程曾验证，仅供参考。
- `单元测试`：请求结构已在本地验证，但未使用真实账号。

## 当前登录流程证据

以下证据验证客户端安全与状态边界，但不等于真实账号的线上功能验证：

- 单元测试覆盖精确 Cookie 名解析、损坏凭证恢复、瞬时校验失败、重试、并发候选会话、
  OAuth 返回代数、取消和部分注销失败。
- 2026-07-27，Android 17 Pixel Fold 模拟器成功加载当前官方登录页。匿名 `10001` 或
  “请先登录”响应会保持为正常未登录状态。
- 同一模拟器的全新 Debug APK 冷启动可以加载论坛主题和公开副本招募列表；打开账号管理会
  进入应用内 WebView，未输入凭证直接关闭后仍保持未登录，进程没有崩溃。
- 设备测试确认加密文件不包含 Cookie 或 User-Agent 明文，且不完整密文记录会被删除。
- 设备测试确认断开连接只删除官方网页与接口域名下精确名为 `ff14risingstones` 的 Cookie，
  并保留其他 WebView Cookie。
- 论坛界面设备测试覆盖紧凑、中等和展开宽度，以及官方帖子内部链接的应用内导航。
- 会话管理界面设备测试确认只显示能力布尔状态，脱敏报告不包含显示名、凭证来源、Cookie
  或 User-Agent。

## 真实账号验证步骤

1. 使用专门的测试账号，在干净测试设备或模拟器上安装独立 Debug 应用。
2. 打开内置官方网页，只记录观察到的主机名，不记录完整重定向地址、查询参数、Cookie、
   账号标识或包含个人数据的截图。
3. 只在内置官方网页中完成登录，确认认证重定向最终返回石之家官方主机。
4. 使用同一 WebView User-Agent 且不添加 `authorization` 请求头，确认捕获的 Cookie 能通过
   `/api/home/GHome/isLogin`。
5. 确认 `getUserInfo` 成功，并在会话管理页看到 `AccountRead` 已验证。只保存“复制脱敏报告”
   生成的能力布尔结果。
6. 重启进程，确认 Keystore 会话能够恢复并重复两项校验。
7. 在应用中断开连接并重启，确认旧会话不再恢复；重新打开 WebView，确认目标 Cookie 已删除，
   同时其他 Cookie 不受影响。
8. 再次登录，确认即使 Cookie 字符串没有变化，认证页返回后仍会重新校验。
9. 每次只验证一个接口，只记录响应码、脱敏消息类别和成功或失败。
10. 只有成功与会话过期行为都明确后，才增加对应能力。

真实验证不会通过提交凭证的方式自动化。

匿名契约测试同时覆盖当前驼峰关系字段和早期下划线字段，避免服务端响应结构切换后详情页被
静默解析为空。
