## 决策与实际责任

用户于本日明确同意：对齐此前本地 iOS 上传器的服务端区间签名策略，不再让不可靠手机时间额外裁决凭据有效期；仍保留区间格式、有限整数、正序、身份和路径校验，不增加缓存或自动重试。依据为此前缓存 iOS `70d0065` 的源码审查及用户批准，不宣称是最新 iOS 或真实服务的完整验证。

`DynamicImageUploadApiService` 仅去除 `startTime > 本机时间` 与 `本机时间 >= expiredTime` 的拒绝条件。仍要求可解析为 Long 整数、`startTime > 0`、`expiredTime > startTime`，按服务端原始秒值构造 `q-sign-time` 与 `q-key-time`，不换算成本机区间、不补默认值。真正是否已过期仍由 COS 拒绝或接受，本批没有取得真实凭据或验证实际服务时钟。

构造函数及命名参数 `nowEpochSeconds` 保留兼容，但不再调用该时钟。对象名原有本机毫秒前缀没有改动；不声称代码所有本机时间用途均被移除。公开 KDoc 已说明此责任。

身份／作用域／attempt 的当前性和取消检查、凭据字段与控制字符校验、固定 HTTPS 对象主机、签名与用途绑定全部保留。发布目录继续要求 `dynamic/` 及安全分段，详见[目录绑定批次](dynamic-publishing-directory-local-20261026.md)。评论 `default`／iOS `dynamic` 合同争议不在本批修改范围。COS 失败不刷新 Web 登录、不自动重试 PUT；令牌 GET 的原有明确认证失败重验行为不变，不增加缓存、重试或持久权限。

## 合成回归与安全边界

所有传输由内存客户端终止，预期之外的新增测试请求直接失败，无 socket 回退。使用合成的非秘密凭据，不真实调用 getCOSTokenI 或 COS，不上传文件、登录或扩大 App 图片 scope。

- 服务端区间 900…2000，手机值为 840、2060 或 Long 两端：两种既有用途均按服务端区间签名，传入的手机时钟调用次数为零。合成 GET／PUT 共两次，能力只在本地模拟成功后完成，未刷新登录。
- 零、负数、相等／反向区间，小数、null、NaN、Infinity、Long 溢出仍在 PUT 前拒绝，不授予能力，attempt 正常关闭。
