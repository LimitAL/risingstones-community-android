# 表情插入的提及光标保护与只读预览

> 当前非折叠选区规则已由[选区文字保留批次](emoji-selection-preservation-20261030.md)更新：取选区末端插入并保留正文。下文“保留旧选区替换”及74项结果是该历史批次范围，不代表现行规则，也不追溯改写历史通过记录。

本地批次 `emoji-mention-caret-20261030`，基线 `2bee8df`。参考客户端缓存70d0065 `RisingStonesMentionDraft.insertText`／`insertionPoint` 与 `RisingStonesMentionTests.textGoesAtTheCursorWithoutSplittingAMention` 明确：折叠光标位于有效已选提及内部时，表情放在整段提及及一个后随ASCII空格之后，不拆开名字或丢弃身份。

新增公开值扩展 `DynamicCommentEditorState.previewEmojiInsertion(number)`，返回不修改原对象的预览状态；编号不在1…46时返回null。预览与发布／评论两个公开VM的实际表情插入共用同一实现，公开VM原权限与提交保护不变。

只有与旧正文匹配且经过非重叠验证的已选跨度可移动折叠光标；普通手打@、无效／陈旧元数据不能取得保护或身份。光标恰好在提及起点／末尾时保持原插入点，内部才向后移动；仅跳过一个ASCII空格，不吞第二空格、NBSP、换行或制表符。UTF16安全偏移及其余提及范围保持。非折叠选区继续原选区替换，不在本批改变混合编辑规则。

该公开方法只做值计算，不读取账号、不校验或扩张认证能力、不保留配额、不发请求。调用方仍须以当前身份／生命周期／编辑状态核对，并用 `preview.text` 执行自身字符上限预检；预览不是提交或授权，也不赋予图片、上传、发布或持久权限。未引入SDK通用1000字上限、缓存或重试。

新增独立8项纯内存回归：最初共用预览仍执行旧插入规则时4项失败；修复后模块74项全通过，含两个公开VM不发送的实际编辑路径。覆盖内部／精确边界、ASCII与其它空白、补充字符及其余范围、普通／陈旧身份、非折叠替换、不修改原值及无效编号。模块lint／构建通过，只有旧构建文件compileSdk升级建议1条。旧受拒发布合同测试未触碰。

新增方法为公开API的增加，不改变已有领域或传输入口。宿主使用本方法必须消费包含本批方法的版本；本地源码组合通过不等于现有Maven制品支持，未发布或资格化Maven独立消费。真实服务／通知、API26–35原生及严格双端未验。历史合成PUT外发未知结论保持，不查询、重试或清理远端。
