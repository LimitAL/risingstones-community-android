## 接口与成功语义

业务接口均位于已审查主机 `https://apiff14risingstones.web.sdo.com/api/home/`。官网传输要求
HTTP 200，表单使用 `application/x-www-form-urlencoded`；数组和对象沿用 `qs` 的键编码。

| 路径 | 方法与字段 | 已确认成功消费 |
| --- | --- | --- |
| `guild/getGuildLabelList` | GET，无参数 | `data` 数组的 `id,name` |
| `guild/setGuildInfo` | POST，`guild_id,key` 和对应同名值 | 业务码 `10000/10002`，不消费实体 |
| `guild/uploadGuildPhoto` | POST，`guild_id,photo_url`，URL 逗号连接 | `10000/10002`，成功后重读相册 |
| `guild/likePhoto` | POST，`photo_id` | `10000/10002` 且 `data` 精确为整数 `1/-1` |
| `guild/commentPhoto` | POST，见下文 | 评论组件仅将 `10000` 视为成功，不消费新 ID |
| `guild/deleteComment` | DELETE，表单 body 的 `comment_id` | `10000/10002`，不消费实体 |
| `guild/deleteGuildPhoto` | DELETE，query 的 `photo_id` | `10000/10002`，成功后返回来源 |

`setGuildInfo` 采用封闭更新类型，仅允许 `guild_pic`、`house_public`、`guild_label`、
`active_time_weekday`、`active_time_weekend`、`guild_describe`。分别提交官方图片 URL、`1/0`、
目录标签 ID 的逗号连接值、`HH:00-HH:00` 和简介。时间端点允许 00 至 24，不猜先后约束；
官网简介非空且最多 200 字。当前标签是名称列表，须通过目录映射回 ID，不能直接提交名称。

评论表单为 `atInfo,content,photo_id,parent_id,root_parent,comment_pic`；mention 项只含
`uuid,character_name`。顶层的两个父 ID 为 0，回复根评论时均为根 ID，回复楼中楼时分别为
被回复 ID 和所属根 ID。正文或图片至少一项非空；官网没有给出可靠正文长度约束，不编造
新评论 ID、正文规则或审核结果。

## 身份、能力与认证撤销

只读入口关系与已验证写能力分开。以下是官方页面的资格条件，不是服务端授权证明：

- 资料编辑：当前角色 `character_id` 等于部队资料 `master_id`。
- 相册上传：当前角色 `characterDetail.fc_id` 等于目标部队；必须校验响应归属，不能只信路由。
- 删除照片：当前社区 UUID 等于照片 `uuid`，或通过照片响应 `guild_id` 重读得到的部队长条件。
- 删除评论：只采用已确认的当前 UUID 等于评论 UUID；共享组件默认开放删除菜单不能作为权限。
- 点赞和发表评论没有可靠的本地管理身份限制；已登录用户明确触发后，仍由实际请求结果确认。

当前身份的准确来源是 `GET api/home/groupAndRole/getCharacterBindInfo?platform=1`。
官网将整个 `data` 保存为角色信息，并将其顶层 `uuid` 保存为社区身份。2026-09-20 当前 Android
会话已只读验证 HTTP 200、业务码 `10000`，顶层 `uuid/character_id` 及嵌套
`characterDetail.fc_id` 都为字符串。标签目录同日返回非空数组，`id` 为数字、`name` 为字符串。
仅记录类型及响应类别，未记录实际身份、名称、数值或个人响应。

新增独立 `GuildWrite` 与 `GuildImageUpload`，复用凭证与精确请求绑定的首次操作授权机制。
基础尝试资格依赖当前已验证 `GuildRead`，管理和归属关系另行校验，不能复用论坛写入能力。
只有 HTTP、业务码和所需负载全部有效后才能授予对应能力；一次点赞不能开放资料管理入口。
缺少真实身份字段时保持未知并隐藏相应管理操作，不能跨用角色 ID 和社区 UUID。

所有写请求最多发送一次。超时、身份冲突、未知 IO 或无效负载不能自动重放；明确认证失败
只可做一次只读会话重验。取消继续传播，换号、撤权或过期后清除草稿与待提交图片，迟到成功
不能更新新会话或授予能力。目录 GET 不授予写能力，上传令牌 GET 不能用于自动能力探测。

## 图片、提交与错误恢复

上传令牌的准确路径是 `api/common/getCOSTokenI`，不位于 `api/home` 下；channel 分别为
头像 `avatar`、相册 `guild`、评论附件 `default`。
临时 COS 凭据仅在内存中使用，Cookie 和登录 User-Agent 只发往官方 API，不转发给对象存储。
沿用已审查的官方 COS 主机，不增加任意上传地址。默认 OkHttp 实现对 COS 隔离宿主默认头、
CookieJar 和拦截器，只保留本次 COS 授权与内容头；回环服务器测试验证实际接收的请求头。
每个 PUT 前及最终业务提交前再次检查
原凭证仍有效；不自动重试上传或登记。复用现有底层上传实现时须保持功能模块分层与旧 API。

官网每张限制 22,020,096 字节，相册最多选择 9 张，头像需 1:1 裁剪。原生选图先形成本地草稿，
明确上传/保存后才签发令牌和上传；相册保存 URI 读取器，每次只读取并上传一张，避免同时
持有九张原始图片。全部上传成功后才发送一次相册登记。部分上传或登记失败
保留明确结果，不能声称已回滚远端对象，公开脚本未证明对象清理或事务接口。
同一会话内的明确重试复用已经上传成功的图片；头像与评论附件也复用已返回的上传结果。
草稿与资格检查共享页面打开时捕获的作用域，换号或丢失 `GuildRead` 后，即使能力恢复，也
不能换用新凭证继续提交旧草稿。切换照片清除回复目标、删除确认和草稿。

头像裁剪、时间选择、简介保存和评论发送各有明确提交动作。删除照片/本人评论提供包含目标
上下文的确认。加载中避免重复提交，失败保留仍可用内容和同一凭证的草稿；只有明确成功后
清稿、重读相应列表或返回来源。图片、点赞初始状态及返回来源已接入读取模型。头像提供拖动、缩放及辅助滑块，
预览和导出共用归一化方形裁剪坐标；先通过 AndroidX ExifInterface 纠正方向，再限制解码尺寸。

## 模块与三档布局

继续使用现有四个 `guild-*` 模块，不新增模块组。domain 增加独立操作服务、封闭修改类型、
标签和显式身份关系；原只读 `GuildService` 保持兼容。data 负责精确表单、关系读取、逐次授权
和结果映射。presentation 管理草稿、上传阶段、提交、确认、成功刷新和迟到请求隔离。
可选 Compose 界面负责编辑、图片选择和操作控件；App 只组装服务与导航。

紧凑宽度小于 600dp 时使用相册与详情单栏导航，编辑和评论在当前资源的可滚动弹层内展开；
600dp 至 839dp 保留相册列表与详情；840dp 起限制阅读和编辑宽度并保留稳定选择。旋转保留尚未提交的非敏感
选择和草稿，明确返回路径；不得因重建自动重复上传或提交。全部用户文本维护三语资源。

## 验证和待补证据

新增单元与合成接口测试覆盖七个端点、精确字段和编码、正负一结果、评论专属业务码、各类
身份混用负例、一次发送、取消、撤权和旧结果隔离。上传覆盖三种 channel、文件边界、最多
9 张、部分失败不登记以及 token/PUT/登记之间换号，确保敏感请求头不外发。

设备测试覆盖明确提交/取消、重复点击、错误后保留、删除返回、作者与来源恢复、配置重建，
并逐档验证 599、600、839、840dp。公共 API 更新后执行独立 Maven 消费、三语/安全门禁和
对应负向测试，同步接入文档、兼容性矩阵和功能清单。

标签目录的原始 ID 已只读确认是数字。仍缺真实写入的权限矩阵、非空成功样本、标签数量
约束、删除他人评论授权、重复
登记/删除幂等及孤立对象清理证据。缺证据项不作为默认可用功能；当前手动登录和消息提醒确认
授权不包含这些真实写入，后续验证应围绕用户明确选择的具体操作进行。
