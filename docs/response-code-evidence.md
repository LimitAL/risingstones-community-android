# 官方响应码证据

记录日期：2026-09-18。本记录依据官方移动 SPA 的公开脚本及本地合成测试；截至本次记录，
已取得的真实请求证据中未出现 `10002`，不据此推断该码的后端名称、触发条件或具体写入结果。

## `10000` 与 `10002` 的接受规则

公开脚本 `app.22e9274d.js` 有以下三处明确证据：

| 位置 | 源码行为 |
| --- | --- |
| 模块 `b775`，响应拦截器 | HTTP 200 且 `code == 10000` 或 `code == 10002` 时，直接返回完整响应；该分支优先于消息文案及其他业务码。 |
| 用户状态的 `actGetisLogin` | 对两码均设置 `SET_ISLOGIN=true`、保存 `data`，并继续读取角色绑定信息。 |
| 用户状态的 `actGetCosToken` | 对两码均保存并返回 `data`。 |

`b775` 还对 `10107` 加上“未绑定收藏家账号”的精确文案设置了独立接受分支；
`10502` 的维护状态处理及 `10108`、`10403` 的提示抑制不代表接受响应。
这些规则不能仅凭相邻数字推广到其他业务码，本次不推断 `10003` 至 `10005` 的含义。

## 投影台当前实现

`glamour-data` 的 `GlamourApiService.perform` 接受 `10000/10002`，两码不再被消息中的
“未登录”等字样覆盖，不触发授权刷新或请求重放。接受响应后，各读取方法继续执行原有
数据结构校验；缺少必要数据仍返回 `MissingPayload`。

收藏夹创建和更新的 `chunk-commons.01300528.js` 模块 `b645`、删除收藏夹的
`chunk-87ae4bd0.7d5fc4f1.js` 方法 `onDeleteFolder`、领取优惠券的
`chunk-78f68c56.3e50ce4c.js` 方法 `onReceiveClick`，均在公共请求返回后直接进入成功分支，
没有再次检查业务码。原生实现对齐此客户端接受策略；这不构成这些接口已实际返回
`10002` 或服务端已完成相应写入的线上证据。

`GlamourResponseCodeTest` 使用合成响应覆盖合法读取、创建／更新／删除／收藏／领取只提交
一次且不刷新授权、缺少读取数据，以及接受码优先于矛盾消息文案。不执行真实写请求。

## 跨模块对齐设计

1. 仍只涉及官方 API 主机与既有请求，不增加主机、端点或模块。公开响应拦截器和登录流程
   均接受 `10000/10002`；本机无头浏览器已重新核对对应公开脚本。
2. `network` 提供仅判断这两个接受码的公共策略，功能 data 复用。它不解析业务数据、不代表
   功能资格，也不授予能力；各读取保留必要负载校验和各自领域错误。
3. 接受码优先于消息文案匹配，不触发授权刷新或写请求重放。签到等既有端点专属接受码仍按
   该端点契约处理；不顺带推断相邻码和其他错误码的含义。
4. 会话校验接受两码但继续只确认会话；账号、个人数据、动态、消息等能力仍需各自探测成功。
   不扩大能力集合，不改变 Cookie 与原登录 User-Agent 的绑定。
5. 不改变 presentation、UI、自适应布局或导航。单元测试覆盖接受码、矛盾消息、必要数据缺失、
   一次写入和明确失效仍拒绝；同步安全门禁、制品与独立 Maven 接入检查。
6. 全部新增响应由合成服务生成，不使用真实写接口制造特定业务码；线上仍只有 `10000` 证据。

## 跨模块实现与边界

- `RisingStonesResponsePolicy.accepts` 仅接受 `10000/10002`。会话校验、论坛（含对象存储
  授权令牌）、招募、账号、投影台、个人数据及探索、动态、消息和个人主页已复用该规则。
  `core` 不包含官方响应码判断，保持与传输无关。
- 基础 `isLogin` 接受码只产生基础会话，不返回任何功能能力；HTTP 鉴权失败不能被响应体中
  的接受码覆盖。旧 `10002`“未登录”拒绝夹具已改为现有未登录码，接受码与矛盾文案另作正例。
- 账号能力校验补上与 `fetchDashboard` 一致的 `data` 对象要求，缺失、空值或数组不能授予
  `AccountRead`；不猜测对象中可选字段。其他模块继续保留其已有必需负载检查。
- 各功能在接受码下不调用授权刷新或身份冲突处理，也不重放写请求。签到端点原有 `10001`
  结果单独保留；没有将该端点语义推广为全局成功码。
- WebView 凭证拒绝分类器不再将带接受码的异常文案当作明确失效。旧式校验器若错误抛出此类
  异常，刷新失败仍返回空授权，但保留当前内存会话和密文；不会凭异常授予新的能力。
- 动态和消息的能力探测继续复用各自读取校验；消息只探测 `getTip`，不调用会确认提醒的列表。
  个人主页继续消费 `AccountRead`，没有新增探测或写入能力。
- 合成测试覆盖合法读取与确认空结果、缺失必需数据、矛盾消息不触发刷新、明确失效仍拒绝，
  以及论坛互动/上传、招募回应、签到/领奖和投影台操作的单次请求。独立 Maven 网络消费面
  同时编译公共策略，原有服务签名不变。

其他错误码、身份冲突恢复方式和旧接口允许的可空字段未在本批重写。`10107` 的特定文案分支
只记录源码证据，不将其纳入公共接受策略。真实线上未观察到 `10002`，不能将本次合成回归
描述为真实写入或全部响应码语义验证。
