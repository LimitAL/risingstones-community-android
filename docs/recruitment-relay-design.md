# 招募分享到动态设计

## 范围与官方契约

功能属于石之家官方社区。2026-09-22 以本机匿名无头移动 Chrome 核对五类招募详情的公开
脚本；入口和分块清单见[后续来源证据](web-parity-plan.md)。详情选择“分享至动态”后只展示
可见范围，没有正文或图片编辑。接口位于 `apiff14risingstones.web.sdo.com`：

`POST api/home/recruit/relay`，`application/x-www-form-urlencoded`，仅发送
`from`、`scope`、`recruid_id`。`from` 为新人 5、副本 6、部队 7、RP 8、其他 9；沿用官方
拼写 `recruid_id`。`scope` 为公开 1、仅互关 2、仅自己 3。页面有登录门禁；匿名写行为未探测。
共享请求策略接受 HTTP 200、业务码 10000/10002；页面只显示成功提示，不依赖响应 data。
接口会创建动态，不能自动探测、重放，也不猜测成功后的新动态 ID。

## 能力与隔离

复用 `DynamicWrite`：该操作创建动态，成功只授予动态写能力；不因招募分享就证明回应招募
或修改招募资料可用。入口要求已验证 `DynamicRead`、明确尝试资格或已有写能力，以及可选
招募转发服务。部队来源另外保留当前招募身份读取门禁。选择范围和查看确认页不发送写请求。

每次确认流程捕获 `DynamicActionScope`，绑定当前凭证及动态读取世代。换号、撤权、返回
或来源替换关闭旧作用域，迟到响应不恢复旧来源。提交期间禁用重复点击；失败保留范围，
只在再次明确点击时重试。成功刷新动态一次并返回原招募详情，不能弹出两层导航。

## 模块与界面

不新增模块组。分享结果是动态，`dynamic-domain` 增加可选 `DynamicRecruitmentRelayService`
与草稿，复用 `DynamicOrigin` 并只接受五类招募枚举、正整数来源 ID 和 `DynamicVisibility`。
`dynamic-data` 在现有动态作用域与请求实现中加入精确表单；不修改已有发布服务抽象方法。
`dynamic-presentation` 管理确认范围、单次提交、错误及清理；`dynamic-ui-compose` 提供
可选原生确认页。它不导入招募 data，也不把招募页面包装成帖子编辑器。

`recruitment-ui-compose` 只新增可选宿主回调，传已读取的 ID、招募板块与标题，不依赖动态
模块。列表内详情及独立详情共用入口。App 映射板块到五类来源，组装服务、会话容器及回流。
部队读取资格撤销时清理带有该来源标题的目的地；其他类型保持原来的阅读资格。

紧凑宽度使用单栏确认页；中等与展开宽度限制内容最大宽度，来源与三种范围始终可读。
旋转保留当前选择和提交状态，凭证内容不写入持久状态。所有文字维护三语；按钮具备语义
和触控目标。无草稿正文或图片，返回可直接关闭确认流程。

## 验证计划

合成接口覆盖五类 from、三档 scope、精确字段、错误、取消、过期作用域及不自动重放；
状态机覆盖重复提交、失败重试、迟到完成、撤权、来源清理与一次性完成事件。设备覆盖
详情入口、范围选择、成功回流、认证清理、配置重建与 599/600/839/840dp；必要时复核真实
窗口。独立 Maven 消费纳入可选服务、确认页和招募导航。更新接入、兼容矩阵和剩余范围，
运行必要单元测试、构建、安全及三语检查。真实账号转发仍须独立验证，不借已有登录或消息
确认授权执行真实写操作。
