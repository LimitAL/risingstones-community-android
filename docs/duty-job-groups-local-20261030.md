# 副本招募职业来源分组

`DutyRecruitmentCatalogs.jobGroups` 是本次职业目录响应的只读分组事实，不增加接口或认证能力。`null` 表示旧构造器／旧快照未提供元数据；空列表表示本次响应没有有效非空组，不代表全局永久没有职业。组名来自响应对象键，不能用行的 `roleType` 推测。官方七组按职能、防护、治疗、近战、远程物理、远程魔法、限制的目录顺序排列；其他组按名称排列，组内有效行保持来源顺序，空有效组不显示。旧行解码与坏结构失败规则不变。

原平面 `jobs` 映射仍按响应原顺序处理，重复ID保留末条；分组保留来源有效行及重复，不借排序改变旧映射。这与参考客户端平面映射重复ID保留首条的旧差异单列，本批不改变旧消费者的既有规则，也不声称真实服务会产生或不会产生重复。

新增属性进入data class相等／复制语义，来源组变化可被观察。旧两字段构造器、无参入口、Kotlin默认构造描述符、两字段copy及旧copy默认mask均保留；旧copy保留新增组事实。新调用可显式 `copy(jobGroups = null)` 标记缺失；自行替换目录行的接入方也应同步维护或清除来源组元数据，SDK不会凭行字段重建它。原component1／2及旧平面Map接口不变。

接入方对缺失元数据可以保持无组标题的原有职业选择，不应假造来源组；已提供且为空的列表不得借旧Map伪装成有来源组。当前编辑器两处使用同一只读投影，原角色／提交／未知结果门控不变，不接新的发布、管理、上传或权限。

验证仅独立合成读取传输、ABI反射与旧Java编译消费者，本地门禁和原生结果由同名批次证据记录；没有真实账号／官方请求、上传／发布或Maven发布／升级资格。旧受拒发布合同测试未改。历史媒体外发结果仍未知，本批不查询、重试或清理远端。
