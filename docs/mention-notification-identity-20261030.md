# 动态编辑器提醒对象按UUID去重

本地批次 `mention-notification-identity-20261030`，基线 `6d58ea4`。参考客户端缓存 `70d0065` 的 `RisingStonesMentionDraft.mentions` 与 `content(of:)` 均按UUID保持首次出现顺序。

修复前，动态发布与评论共用的编辑投影按完整对象（UUID＋角色名）去重；同一UUID在正文以旧名／新名各被选中时，会生成两条提醒对象。只确认本地参数差异，未访问真实服务或证明服务端会重复通知。

现在仅改变 `dynamic-presentation` 私有 `prepareContent` 的收集规则：仍先验证／排序可见跨度，按UUID保留正文首次出现的对象，其他同UUID跨度继续以各自名字和标识输出HTML。名字不按最新缓存覆写，不按展示名合并不同UUID，也不规范化UUID。普通手打@、失配／重叠元数据、移除后的普通文本仍不生成提醒对象。评论与发布不同表情HTML规则不变。

新增独立6项纯内存回归，首次6项中3项失败复现差异，修复后模块57项全通过；覆盖同UUID改名、同名异UUID、正文顺序优先于元数据顺序、Unicode／转义、失配及重叠范围、普通@／移除、段落与选区不影响名单。模块lint与构建通过，只有未修改构建文件的compileSdk升级建议1条，不改工具链／基线。公开边界／层级／文档／源码检查单列本批结果。

不增加公共API、字段、端点、权限、凭据、网络、缓存或自动重试，不改变传输层对直接手工构造草稿的既有处理；本批保证编辑器生成的名单，不宣称所有调用者输入均由传输层重新去重。旧消费者ABI不变；本地源码修复不等于已发布Maven制品。

全部证明为合成数据和纯编辑投影，没有HTTP客户端、真实凭据、上传、业务发送或设备操作。此前受拒的旧发布合同测试插入未重试／绕过。真实服务、生产通知结果及独立Maven消费未验，历史合成PUT外发未知事实仍保留。
